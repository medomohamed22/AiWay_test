# AiWay

منصة Pi للشات، أدوات الذكاء الاصطناعي، إنشاء الصور، الرصيد والدفع، الدعم، دليل التطبيقات ولوحة الإدارة.

## التشغيل

المتطلبات: Node.js 24 وnpm. هذه النسخة تستهدف قاعدة Supabase الموجودة للمشروع.

1. شغّل `npm ci --ignore-scripts`.
2. انسخ `.env.example` إلى `.env.local`، واملأ القيم المطلوبة.
3. أنشئ مفتاح JWT عشوائيًا بطول مناسب باستخدام:
   `node -e "console.log(require('node:crypto').randomBytes(48).toString('base64url'))"`.
4. راجع قاعدة البيانات كما هو موضح أدناه، وطبّق migrations على نسخة تجريبية.
5. شغّل `npm run dev` وافتح `http://127.0.0.1:3000`.

خادم التطوير يدعم مسارات API والملفات العامة. تسجيل Pi والدفع الحقيقيان يحتاجان عنوان التطبيق المسجّل في Pi وبيئة Pi المناسبة. لا تضع مفاتيح Supabase أو Pi أو OpenRouter في ملفات الواجهة.

## قاعدة البيانات والترقية

الـZIP الأصلي لم يحتوِ على SQL إنشاء القاعدة أو تعريفات الدوال القديمة. لذلك ملفات `supabase/migrations` **ترقية إضافية لقاعدة موجودة**، وليست مثبتًا لقاعدة فارغة.

قبل النشر:

1. خذ نسخة احتياطية من قاعدة Supabase، وانسخها إلى staging.
2. شغّل `supabase/preflight.sql`، وهو فحص قراءة فقط. راجع أنواع المعرفات UUID، الحقول التي تستخدمها API، وتعريفات الدوال القديمة.
3. القاعدة المطلوبة تحتوي على users، payments، conversations، messages، generated_images، ai_usage_reservations، support_threads، support_messages. إصدار PostgreSQL المطلوب 15 أو أحدث.
4. راجع توقيعات complete_token_purchase، reserve_ai_tokens، finalize_ai_tokens، release_ai_tokens، ودوال التجربة وانتهاء الصلاحية وحدود الطلبات. ملفات الترقية تحتفظ بهذه الدوال وتستدعي دالة الشراء الحالية داخل معاملة محمية.
5. طبّق الملفات الثلاثة بالترتيب: `202610020001_maintenance.sql` ثم `202610020002_pages.sql` ثم `202610020003_rpc_permissions.sql`.
6. إذا كانت هناك payment_id مكررة أو معاملات مكتملة تحمل txid مكررًا، الترقية تتوقف؛ سوِّ السجلات أولًا. لا تحذف سجلًا ماليًا دون مراجعة.
7. اختبر على staging: تسجيل Pi، شراء باقة وإعادة callback، شات مدفوع وتجريبي وبث الرد، متابعة الرد، المرفقات، تنزيل الملفات/ZIP، الصور وتنزيلها وحذف المحادثة، الدعم، إعدادات الإدارة ودليل التطبيقات.
8. طبّق SQL قبل نشر الكود الجديد. اختر وقتًا مناسبًا لإنشاء الفهارس، لأن الملفات تستخدم معاملات وفهارس عادية قد تنتظر أقفالًا على الجداول الكبيرة.

الدوال الجديدة متاحة لـservice_role فقط. صلاحيات تنفيذ الدوال المالية القديمة أصبحت للـserver أيضًا؛ هذا يناسب المصادقة الحالية التي تستخدم JWT مخصصًا وتتحقق منه داخل API. لو توجد تطبيقات أخرى تستدعي هذه RPCs مباشرة، راجعها قبل تطبيق ملف الصلاحيات.

لم تُعدَّل سياسات RLS الأصلية لجميع الجداول، لأن تعريفاتها غير موجودة في المصدر. راجعها منفصلة في قاعدة staging؛ نجاح الاختبارات المحلية لا يؤكد إعدادات قاعدة الإنتاج.

## الاختبارات والفحوص

```sh
npm run verify
```

يشغّل التحقق من الصياغة والاستيرادات وروابط ملفات HTML، فحص ESLint، الاختبارات وبناء الملفات العامة.

اختبارات المال تنشئ PostgreSQL محليًا مؤقتًا، وتستخدم حتى 12 اتصالًا حقيقيًا. على Windows تعمل من الحزمة المضمنة. على Linux يمكن استخدام PostgreSQL محلي/حاوية مع قاعدة منفصلة باسم `aiway_test`:

```sh
TEST_DATABASE_URL=postgres://postgres:test-only-password@127.0.0.1:5432/aiway_test npm test
```

الاختبارات ترفض قاعدة بعيدة أو اسم قاعدة غير مخصص للاختبار. يجب أن تكون قاعدة الاختبار فارغة عند البداية. عند استعمال PostgreSQL المضمن على نظام يحتاج symlinks، اسمح فقط ببرنامج تثبيت حزمة `@embedded-postgres` المناسبة وفق تعليماتها.

GitHub Actions يشغّل نفس الفحوص على Node 24 وPostgreSQL 17. لا يحتاج مفاتيح خدمات حقيقية.

الاختبارات تشمل تكرار الدفع والتزامن، منع إعادة استخدام txid، ملكية البيانات، ذرية تعديل الرصيد وسجل الإدارة، فشل Pi/OpenRouter/Storage، مهلة قراءة رد الخدمة، حساب استخدام الصور مرة واحدة، الصفحات والبحث، بث الشات، تنزيل الملفات وZIP، وتوافق مسارات الحساب.

اختبارات SQL تستعمل schema تجريبيًا يمثل توقيعات القاعدة القديمة. يجب مقارنة هذه التوقيعات وتعريفات دوال الرصيد بقاعدة المشروع الفعلية قبل النشر.

## تنظيم الكود

| المسار | المسؤولية |
|---|---|
| `api/` | مداخل Vercel؛ أسماء المسارات القديمة محفوظة |
| `server/features/auth/` | تسجيل Pi، جلسات JWT والتحقق من المستخدم |
| `server/features/chat/` | الشات والبث والمتابعة والتنزيل |
| `server/features/images/` | إنشاء الصور وحفظها وتنزيلها وتنظيفها |
| `server/features/payments/` | اعتماد الدفع وإتمامه واسترجاعه |
| `server/features/admin/` | الإحصائيات والإعدادات وسجل الإدارة |
| `server/features/conversations/` | المحادثات والدعم والإعلانات |
| `server/domain/` | التسعير، الرصيد، الحجز، اختيار النماذج، إعدادات المميزات |
| `server/providers/` | HTTP وPi وOpenRouter وStorage وTelegram |
| `server/data/` | ملكية البيانات وتقسيم النتائج |
| `server/core/` | عميل القاعدة، HTTP ومعالجة الأخطاء |
| `supabase/` | فحص القاعدة وملفات ترقيتها |
| `tests/` | اختبارات السلوك وتكامل PostgreSQL |

`api/_lib.js` يظل واجهة تصدير توافقية. الوحدات الداخلية تستورد مسؤولياتها مباشرة.

الواجهة الحالية بقيت JavaScript، وتم تعديل الأجزاء التي تحتاج صفحات/بحثًا فقط. لم يُغيَّر إطار الواجهة أو لغة البرمجة أثناء هذه الإصلاحات.

## الصفحات والإحصائيات

- المحادثات: 40 سجلًا افتراضيًا وزر «تحميل محادثات أكثر».
- مستخدمو الإدارة: 40 سجلًا، السابق/التالي، وبحث داخل القاعدة. تصدير CSV يجمع كل الصفحات عند طلبه.
- المدفوعات وسجل الإدارة والنسخ والأخطاء: صفحات محدودة وزر تحميل المزيد.
- رسائل الدعم تُقرأ على دفعات مع استمرار عرض التاريخ القديم كاملًا.
- دليل التطبيقات: cursor جديد `page:OFFSET` يتوافق مع ترتيب النتائج، مع استمرار قبول cursor الزمن القديم.
- ترتيب الصفحات يضيف معرفًا عند تساوي التواريخ. الصفحات التي تستخدم offset ليست snapshot؛ عند وصول سجلات جديدة أو إعادة ترتيب المحادثات، حدّث القائمة لقراءة أحدث ترتيب.
- تجميع الإيرادات والاستخدام والنشاط والنماذج يتم داخل PostgreSQL. صور لها رسالة assistant تُحسب من الرسالة مرة واحدة؛ الصور القديمة التي ليس لها رسالة محفوظة تظل محسوبة.

## النشر والتراجع

Vercel يشغّل `npm ci --omit=dev --ignore-scripts` ثم `npm run build`. البناء ينشر قائمة ملفات الواجهة المسموح بها إلى `public/`؛ ملفات server وSQL والاختبارات والبيئة لا تدخل المجلد العام. روابط CSS وJavaScript في ملفات HTML المنشورة تحمل بصمة محتواها لتحديث cache عند تغيّر الكود. إعدادات CSP ومسارات إعادة الكتابة القديمة محفوظة.

ملفات الترقية تضيف دوال وجداول وفهارس، وتحافظ على دالة الشراء القديمة. عند الحاجة للتراجع عن الكود يمكن إعادة النسخة السابقة مع إبقاء الجداول الإضافية. لا تتراجع عن سجلات الشراء أو تعديلات الرصيد المكتملة، ولا تحذف receipts أو سجل الإدارة لاسترجاع الكود.

تفاصيل التنفيذ والتحقق موجودة في [docs/IMPLEMENTATION.md](docs/IMPLEMENTATION.md).
